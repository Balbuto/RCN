# Безопасность и ограничения

## Исправления безопасности в v3.1

- пользовательский ввод не встраивается напрямую в inline Python-код;
- JSON-конфигурация записывается атомарно через временный файл и `os.replace()`;
- один advisory file lock покрывает весь цикл чтения, изменения и записи конфигурации, поэтому параллельные вызовы редактора не теряют изменения;
- legacy-значения boolean разбираются явно: `"false"` не считается истинной непустой строкой и не включает GeoIP;
- параллельные операции `update` и `apply` сериализуются через `flock`;
- обновление `ipset` выполняется атомарно через временный set и `swap`;
- checksum manifest проверяется в GitHub Actions и в checklist публикации.

## Что остаётся важным для эксплуатации

### 1. Скрипт работает от root

Это необходимо для управления `iptables`, `ipset` и `systemd`. Перед включением GeoIP на удалённо администрируемом сервере внимательно проверьте правила стран, allow и deny.

### 2. GeoIP по странам зависит от внешнего источника CIDR

Используется `ipdeny.com`. Если источник недоступен:
- уже закэшированные country CIDR будут использованы из локального кэша;
- если кэша нет, обновление конкретной страны не выполнится.

### 3. IPv6 не поддерживается

Текущая реализация создаёт IPv4 `ipset`-наборы (`family inet`). IPv6-адреса и сети отклоняются меню, `config_tool.py` и кодом применения GeoIP, а не передаются в несовместимый набор.

### 4. GeoIP по странам — это CIDR-фильтрация, а не GeoIP БД уровня MaxMind

Это осознанное упрощение. Привязка идёт по опубликованным country-block спискам.

### 5. Скрипт не должен запускаться на сервере, где правила iptables управляются другой сложной системой

Например:
- собственным orchestration-layer;
- panel/hosting firewall manager;
- внешней CM-системой, которая полностью перезаписывает `iptables`.

В таком случае сначала нужно определить, кто является источником истины для firewall.
