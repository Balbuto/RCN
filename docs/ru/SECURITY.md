# Безопасность и ограничения

## Исправления безопасности в v3.1

- пользовательский ввод не встраивается напрямую в inline Python-код;
- JSON-конфигурация записывается атомарно через временный файл и `os.replace()`;
- один advisory file lock покрывает весь цикл чтения, изменения и записи конфигурации, поэтому параллельные вызовы редактора не теряют изменения;
- legacy-значения boolean разбираются явно: `"false"` не считается истинной непустой строкой и не включает GeoIP;
- параллельные `update` и `apply` сериализуются через `flock`;
- обновление `ipset` выполняется атомарно через временный set и `swap`;
- checksum manifest проверяется в GitHub Actions и в документированном checklist релиза.

## Что важно в эксплуатации

### Скрипты работают от root

Это необходимо для управления `iptables`, `ipset` и `systemd`. Перед включением GeoIP на удалённо администрируемом сервере внимательно проверьте правила стран, allow и deny.

### GeoIP по странам зависит от внешнего источника CIDR

Используется `ipdeny.com`.
Если источник недоступен:
- будет использован локальный кэш, если он уже есть;
- если кэша нет, обновление country-set не выполнится.

### IPv6 не поддерживается

Текущая реализация создаёт IPv4 `ipset`-наборы (`family inet`). IPv6-адреса и сети отклоняются меню, `config_tool.py` и кодом применения GeoIP, а не передаются в несовместимый набор.

### Country GeoIP — это CIDR-фильтрация, а не MaxMind GeoIP DB

Привязка идёт по опубликованным country-block спискам.

### Не рекомендуется запускать на сервере, где `iptables` полностью управляется внешней системой

Например:
- orchestration-layer;
- firewall manager в панели;
- CM-система, полностью перезаписывающая `iptables`.
